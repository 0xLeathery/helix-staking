    ```rust
    // === Phase 24: Boost check ===
    // Check if this is a boosted stake and apply multiplier or revoke
    let (boost_adjusted_rewards, boost_applied) = if stake.seed_balance_at_stake > 0 && !stake.boost_revoked {
        // Boosted stake: need seed ATA in remaining_accounts[0] to check current balance
        if ctx.remaining_accounts.is_empty() {
            // No seed ATA passed -- treat as non-boosted for this claim
            // (Client must pass seed ATA to get boost; omission means base rewards only)
            (loyalty_adjusted_rewards, false)
        } else {
            let seed_ata_info = &ctx.remaining_accounts[0];
            // Read current seed balance from token account (amount at offset 64, 8 bytes LE)
            let data = seed_ata_info.try_borrow_data()?;
            let current_seed_balance = if data.len() >= 72 {
                u64::from_le_bytes(data[64..72].try_into().unwrap())
            } else {
                0u64
            };

            if current_seed_balance >= stake.seed_balance_at_stake {
                // Boost active: apply 10% multiplier
                let boosted = apply_boost_multiplier(loyalty_adjusted_rewards)?;
                (boosted, true)
            } else {
                // Balance dropped below snapshot: REVOKE permanently
                // Per BOOST-05: revocation is permanent per stake
                // Per user decision: mint base rewards (non-boosted), set boost_revoked = true
                // NOTE: We set the flag BEFORE the CPI mint (Check-Effects-Interactions)
                let stake_mut_for_revoke = &mut ctx.accounts.stake_account;
                stake_mut_for_revoke.boost_revoked = true;

                emit!(BoostRevoked {
                    slot: clock.slot,
                    user,
                    stake_id,
                    current_balance: current_seed_balance,
                    required_balance: stake.seed_balance_at_stake,
                });

                (loyalty_adjusted_rewards, false)
            }
        }
    } else {
        // Not a boosted stake, or already revoked
        (loyalty_adjusted_rewards, false)
    };
    ```

    Then update the BPD + total calculation to use `boost_adjusted_rewards` instead of `loyalty_adjusted_rewards`:
    ```rust
    let bpd_bonus = stake.bpd_bonus_pending;
    let total_rewards = boost_adjusted_rewards
        .checked_add(bpd_bonus)
        .ok_or(HelixError::Overflow)?;
    ```

    After the existing `emit!(RewardsClaimed { ... });`, add a conditional boost event:
    ```rust
    if boost_applied {
        let boost_amount = boost_adjusted_rewards
            .checked_sub(loyalty_adjusted_rewards)
            .unwrap_or(0);
        emit!(BoostedRewardsClaimed {
            slot: clock.slot,
            user,
            stake_id,
            base_amount: loyalty_adjusted_rewards,
            boost_amount,
            total_amount: total_rewards,
        });
    }
    ```

    IMPORTANT considerations:
    - The `boost_revoked = true` write happens BEFORE the `mint_to` CPI (Check-Effects-Interactions pattern, same as `reward_debt` update). This is critical for preventing double-revocation exploits.
    - When boost is revoked during claim, the user still gets base rewards (non-boosted). The transaction does NOT fail.
    - BPD bonus is added AFTER boost, so boost does NOT amplify BPD (per user decision: "BPD bonus is NOT amplified by boost -- stays as a separate additive term").
    - Non-boosted stakers (seed_balance_at_stake == 0) skip the entire block -- zero performance impact.
    - The `stake` immutable borrow is used to read seed_balance_at_stake and boost_revoked before the mutable borrow for revocation. Be careful with Rust borrow checker -- may need to copy values before the mutable borrow block.

    Also handle the borrow checker issue: `stake` is an immutable reference from `ctx.accounts.stake_account`. After the boost check, the code takes `&mut ctx.accounts.stake_account` for reward_debt update. The revocation write (`stake_mut_for_revoke.boost_revoked = true`) happens inside the boost check block, but it borrows `ctx.accounts.stake_account` mutably while `stake` is still live. Fix: read `seed_balance_at_stake` and `boost_revoked` into local variables BEFORE the boost check:
    ```rust
    let seed_balance_at_stake = stake.seed_balance_at_stake;
    let boost_revoked = stake.boost_revoked;
    ```
    Then use these locals in the boost check instead of `stake.seed_balance_at_stake` and `stake.boost_revoked`.
